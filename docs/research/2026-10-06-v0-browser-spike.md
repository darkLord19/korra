# v0 browser spike: findings

**Date:** 2026-10-06 · **Code:** `apps/spike-local` (deleted once `apps/local` replaced it; see git history at `da735ad`) · **Scope:** `docs/design/v0-client-only-and-declarations.md` §A7

## Verdict: feasible

These backend use-cases run unchanged in the browser, on PGlite persisted to IndexedDB:
- `saveBank`, `saveProfile`, `getOnboarding`;
- `requestUpload`, `confirmUpload`, `runIngest` (the Deel CSV);
- `getMonthState`;
- `renderPack`.

The data survives a page reload, and a backup round trip works.

## Constraints to carry forward

| Topic | Finding | Decision |
|---|---|---|
| **Bundler** | Turbopack (the Next 16 default) breaks PGlite in production builds: `h.instantiateWasm is not a function` | Build `apps/local` with `next build --webpack` and run it with `next dev --webpack` until this is fixed upstream |
| **Multiple tabs** | Plain `idb://` loses writes silently across tabs: the last tab to write wins, and nothing raises an error | **Use `PGliteWorker` with leader election.** Six out of six writes survived, it fails over when the leader tab closes, and only the leader runs migrations |
| **Cold boot** | Throws one harmless `ErrnoError` page error during initdb | e2e tests must tolerate it on first run |
| **Download size** | First use loads about 10.7 MB as measured. About 4.7 MB of that is WASM and data, which shrinks with brotli. The pdf.js worker adds about 0.3 MB. Next serves `pglite.data` uncompressed (Vercel compresses it) | Load PGlite only on the first action that needs it, and show progress |
| **Timings (cold → warm)** | PGlite boot 640 → 95 ms. Migrations 22 → 0.8 ms. Deel `runIngest` 5 ms. `renderPack` 36 ms. pdf.js text 51 ms. Full flow about 880 ms cold | Acceptable |
| **CSP** | Works with zero violations and no requests leaving the origin: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval' <sha256 hashes of inline scripts>; connect-src 'self'; worker-src 'self' blob:; img-src 'self' blob: data:; style-src 'self' 'unsafe-inline'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'` | `'wasm-unsafe-eval'` is required. Next's inline scripts need hashes, which means a fixed build id and a two-pass build (`scripts/csp-hashes.mjs`) |
| **pdf.js** | `pdfjs-dist` 5.7 reads the text layer in the browser, with its worker served from our own origin | About 121 KB gzipped for the main chunk, plus a 365 KB worker loaded only when needed |
| **Backup** | `dumpDataDir("gzip")` then `loadDataDir` round-trips correctly. A tiny dataset dumps to about 4.7 MB gzipped. Uploaded files are **not** in the dump | The `.korra` file is a zip of the dump plus every blob plus a manifest |
| **Blob store** | The spike used memory only | An IndexedDB blob store is still to build |

## Isomorphic split (done in the spike)

These entries are new and work on both server and browser:
- `@korra/db/iso`, `@korra/ingest/iso`, `@korra/packs/iso`, `@korra/backend/core`;
- `@korra/db/browser`, with `createBrowserDb` and a bundled migrator (`browser-migrate.ts`, generated by `db:bundle-migrations`).

The existing entries now re-export them behind `server-only`. Changes made along the way:
- `node:crypto` was replaced by Web Crypto.
- Supabase, Resend and the server-side `createDeps` were moved out of the shared modules.

A depcruise rule, `iso-entries-stay-isomorphic`, enforces the split.

## Storage durability (sources)

- **Safari's 7-day rule:** Safari deletes all script-writable storage for a site, IndexedDB included, "after seven days of Safari use without user interaction on the site". Source: https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/, and MDN, *Storage quotas and eviction criteria*.
- **Home Screen apps** keep their own counter of days of use, so actively used installed apps are effectively exempt.
- **`persist()`:** Safari and Chrome approve or deny it automatically from heuristics; Safari, for example, favours Home Screen apps. Firefox asks the user.
- **Quota:** up to 60% of disk for a browser app (https://webkit.org/blog/14403/updates-to-storage-policy/).
- **What the copy should say:**
  - recommend "Add to Home Screen" on Safari;
  - call `persist()` and show the result;
  - make backups routine.
