# AD code: what it is, whether we can look it up, and whether a services EDF needs it

**Date:** 2026-10-08 · **Primary sources:** RBI notification FEMA 23(R)/2026-RB (https://rbi.org.in/Scripts/BS_FemaNotifications.aspx?Id=13277); RBI A.P. (DIR Series) Circular No. 20, 16 Jan 2026 (https://www.rbi.org.in/Scripts/NotificationUser.aspx?Id=13278&Mode=0); RBI circular on CISBI, RBI/2019-20/81 (https://www.rbi.org.in/commonman/Upload/English/Notification/PDFs/NOTI81111019.pdf); ICEGATE "Advisory for Authorized Dealer Code (ADC) Bank Account Registration", 6 Sep 2022 (original https://old.icegate.gov.in/Download/AD_Code_Bank_Account_Registration_Advisory_Final.pdf no longer resolves; read from https://web.archive.org/web/2023id_/https://old.icegate.gov.in/Download/AD_Code_Bank_Account_Registration_Advisory_Final.pdf); ICES message format documents on icegate.gov.in; JNCH Customs Public Notice 93/2020 (https://www.jawaharcustoms.gov.in/pdf/PN-2020/PN-93-2020.pdf); bank EDF forms (HDFC, ICICI, Axis; see the 2026-10-07 HDFC note)

## Question

Our bank form makes the exporter type an "AD code" (`BankForms.tsx`, required; `ad_code NOT NULL` in the DB). Freelancers usually do not know theirs.

1. Can the AD code be worked out from bank and branch (for example from the IFSC)? What is it, who issues it, what format does it have, is there an official list or lookup, and how does an exporter get theirs?
2. Must the AD code be on a services EDF (no shipping bill, no ICEGATE registration)? Who fills it, and what happens if it is blank?

## Answers

1. **Mostly no. Do not try to derive it from the IFSC.** (Confidence: high that there is no official IFSC-to-AD-code mapping; medium on the format.)
   - **Who allots it.** RBI allots AD codes to bank branches through its branch master (formerly MOF, now CISBI), alongside BSR codes. The bank only passes the code on to the customer, usually in an "AD code letter" or bank authorisation letter.
   - **What it looks like (inference).** It is a short branch code, 7 characters in every primary example found, and almost certainly the AD branch's BSR Part-I code: a 3-digit bank code plus a 4-digit branch code.
   - **"14 digits" is probably wrong.** The widely repeated "14-digit AD code" comes only from aggregators. It is likely the full BSR Uniform Code Number (Part-I plus Part-II, 7 + 7). The Customs message spec only has room for 10 characters.
   - **No public lookup by IFSC.** Customs (ICEGATE) has an official "AD Code Help" lookup, but only behind login, searchable by branch address, and with no API. RBI's public DBIE Bank Branch Locator lists each branch's Part-I code and its authorised-dealer category; I could not confirm the fields hands-on, and it does not appear to include IFSC. No bank I checked publishes AD codes.
   - **The relevant code may not be your branch's.** For a services EDF, the code that matters is the code of the AD branch that processes the exporter's forex. That may be a centralised trade branch rather than the account branch. ICICI's own EDF pre-fills its Mumbai corporate-office code.
2. **No primary source makes the AD code an exporter-mandatory field on a services EDF.** (Confidence: medium, because the RBI Annex PDF itself is still behind a CAPTCHA.)
   - **It is in the form.** The RBI Annex has an "AD code" field in Part 1.
   - **No bank marks it mandatory.** HDFC's and Axis's forms leave it blank and unmarked. ICICI's form does not star it as mandatory (it stars other fields) and pre-fills its own code.
   - **The bank does the EDPMS entry.** Reg. 18(1)(b) makes the AD bank enter services EDFs into EDPMS itself, and the bank receiving the EDF is the AD.
   - **Blank is low risk.** If the exporter leaves it blank, the likely outcome is that the bank fills it in or asks for it, not that the EDF is rejected. This is inference: no bank states it.

## Findings: what the AD code is (Q1)

### Who allots it, and how it relates to BSR codes

1. **RBI allots it, per branch.** RBI/2019-20/81 (11 Oct 2019), para 2: "The Reserve Bank maintains the directory of all bank branches / offices / … in India, [known as the 'Master Office File' (MOF) system] … The system allots Basic Statistical Return (BSR) code / Authorised Dealer (AD) code to bank branches / offices / NAIOs / CSPs." Para 3 says CISBI (https://cisbi.rbi.org.in) replaces MOF. (https://www.rbi.org.in/commonman/Upload/English/Notification/PDFs/NOTI81111019.pdf) The same branch record in the CISBI proforma also carries MICR (item 10), IFSC (item 11) and "Forex Office … A Category / B Category" (item 16.2.3). So RBI holds IFSC and the branch code side by side, but does not publish that join.
2. **Commercial-bank CISBI codes.** RBI/2018-19/228 (28 Jun 2019) says MOF formerly allotted BSR and AD codes, and that "BSR code for the new BOs, offices etc. would be allotted as alpha-numeric codes (instead of numeric codes as hitherto)". (https://www.rbi.org.in/Scripts/NotificationUser.aspx?Id=11609, as summarised by WebFetch; the circular PDF is CAPTCHA-blocked.)
3. **BSR structure.** Part-I is 7 characters: a 3-digit bank code plus a 4-digit branch code. Part-II is another 7: district and revenue-centre codes. Together they make the "Uniform Code Number". **Source quality:** this comes from search-result extracts of RBI's BSR handbook (https://rbidocs.rbi.org.in/rdocs/Publications/PDFs/83850.pdf); I did not read the PDF myself because of the CAPTCHA. RBI's Directory of Bank Offices confirms "Part-I and Part-II of Uniform Code Number of 7 digits each … are maintained in the MOF" (https://www.rbi.org.in/dob/DOB.html).

### Format: 7 characters in every primary example

1. **ICEGATE screenshots show 7-digit codes.** In the ICEGATE ADC advisory (6 Sep 2022, pages 7 and 8; Wayback URL above), the AD code column reads HDFC BANK LTD. `0510005`, VIJAYA BANK `0390647`, THOMAS COOK(INDIA) LTD `6920099` / `6920005`. These are sample rows from a test system (`localhost:8080`, test IRNs and IDs), and their statuses prove nothing about format: the 7-digit Vijaya row is "System Rejected" too. The "AD Code Help" screenshot lists Syndicate Bank branches as `0330123`, `0330124`, … `0330085`, one per branch address.
2. **The ICES message format has room for 10 characters.** "Authorized Dealer Code", type C, length 10, in the shipping-bill message. It is "M (Optional For Non-NFEI SBs)" [sic], and the explanation reads "Bank code, where the foreign exchange remittance wouldtake placehas to be mentioned" (ICES/Exports message format v3.2, May 2024: https://www.icegate.gov.in/sites/default/files/2024-05/%2810.05.24%29%20ICES_1.5_CHA_Customs_Exports_Mesg_Format_Ver_3.2%20%283%29%20%281%29.pdf). The Bill of Entry message has the same field, C 10 (BE message format v2.15, Jul 2024: https://www.icegate.gov.in/sites/default/files/2024-11/BE-Message-format-2-15-20July2024_0.pdf). A 14-digit code would not fit.
3. **ICICI's EDF shows 7 digits.** It reads "Authorised Dealer (AD) Code: 6390002", with AD name "ICICI BANK LIMITED, Mumbai & CORPORATE OFFICE BRANCH, ICICI TOWERS BKC" (https://www.icici.bank.in/content/dam/icicibank/icici-assets/nri-banking/export-declaration-form-development.pdf; PDF created 1 Oct 2026, author "/REMT/IBANK/THANE").
4. **The prefixes match BSR bank codes.** A government BSR directory (Controller of Pension Accounts, Ministry of Finance, https://cpao.nic.in/Ministry/BSR.php) keys its per-bank download links by base64-encoded BSR bank codes. They decode to HDFC = `051`, ICICI = `639`, Syndicate = `033`, Axis = `636`, SBI = `000`, Kotak = `018`, and so on. These are the same prefixes as the AD codes above (`051`0005, `639`0002, `033`0123).
5. **Inference, not verified:** the AD code is the BSR Part-I code of the AD (forex-authorised) branch. The "14-digit AD code" in nearly every blog (Skydo, Drip, Bajaj, IndiaFilings, etc.) is probably Part-I plus Part-II as printed on some bank letters. No primary source I found defines a 14-digit AD code. Aggregators also disagree on its internal structure ("4+4+6", etc.), and at least one lists SWIFT BICs (`SBININBBFXD` etc.) as "AD codes", which is wrong.

### IFSC vs AD code

1. **Customs treats them as separate identifiers.** JNCH Public Notice 93/2020 (29 Jul 2020), Annexure-A "Bank Authorisation Letter", lists "1. BANK ACCOUNT NUMBER: 2. AD CODE: 3. IFSC:" as separate lines that the branch certifies. The AD code is "for the purpose of foreign remittance" and the IFSC is "for the purpose of IGST refund /Drawback" (https://www.jawaharcustoms.gov.in/pdf/PN-2020/PN-93-2020.pdf).
2. **A bank merger can change the AD code.** The modified Annexure-A for bank mergers has separate "Old/New AD Code" and "Old/New IFSC" rows (JNCH PN 40/2021, https://www.jawaharcustoms.gov.in/pdf/PN-2021/PN-40-2021.pdf).
3. **No published mapping.** RBI's CISBI holds both codes per branch (see above), but I found no public dataset that joins IFSC to AD code. An IFSC lookup can give us the bank, which fixes the first 3 characters (inference). It cannot give us the AD branch.

### Account branch, or a central branch?

1. **Branches differ in forex authority.** CISBI and the DBIE locator classify branches by AD category (A/B/C), so not every branch is an AD branch.
2. **Customs takes "the AD code of the Bank Branch"**: "User is asked to select bank name and enter valid AD code of the Bank Branch" (ICEGATE advisory p. 8). The ICES spec defines it as the bank code "where the foreign exchange remittance would take place".
3. **ICICI's services EDF uses a central code.** It pre-fills `6390002` with the Mumbai corporate-office branch. This suggests ICICI processes services EDFs centrally, and that the account branch's own code would be wrong on an ICICI EDF.
4. **Inference:** for an account at a non-AD branch, the bank gives the code of its linked AD or trade-processing branch. Which code a bank uses for services EDFs is the bank's choice and is not derivable from public data.

### How an exporter gets theirs

1. **Ask the bank for an "AD code letter" / bank authorisation letter.** Customs' format is JNCH PN 93/2020 Annexure-A, which carries the AD code, IFSC and account number and is signed by the issuing authority with the bank stamp.
2. **ICEGATE.** Registered users see their registered AD codes on the "Authorized Dealer Code" dashboard under Bank Account Management. Since ICES Advisory 10/2022 (14 Jun 2022), one registration at one port works for all ports (https://bombaychamber.com/wp-content/uploads/2022/06/ices-advisory-no-102022-422350.pdf; mirrored as JNCH PN 33/2022, https://www.jawaharcustoms.gov.in/pdf/PN-2022/PN-33-2022.pdf). Pure service exporters normally have no ICEGATE registration.
3. **Earlier documents.** Goods exporters have the code on their shipping bills (ICES field above). RBI-format remittance forms have a bank-filled "AD Code No." box: RBI Form A2 says "(To be filled in by the Authorised Dealer)" (https://www.rbi.org.in/upload/ECM/pdfs/a2.pdf), and Axis's remittance form puts "AD Code No" under "For Office use" (https://www.axis.bank.in/docs/default-source/business-banking/direct-import-bill.pdf). Not verified: whether inward-remittance advices or e-BRCs show it.
4. **Simplest for a freelancer:** ask the bank's trade or forex desk which AD code it uses for services EDFs.

## Findings: is the AD code needed on a services EDF? (Q2)

### Current rules

1. **The regulations.** FEMA 23(R)/2026-RB, in force 1 Oct 2026 (https://rbi.org.in/Scripts/BS_FemaNotifications.aspx?Id=13277):
   - **No mention of the AD code** in the regulation text (WebFetch search of the page).
   - **EDF required for every services export.** Reg. 3(2): "An exporter of services shall furnish to the specified authority, a declaration in EDF specifying the amount representing the full export value of services, within 30 days from the end of month in which invoice for services has been raised". Provisos: (a) a single EDF per month, (b) non-software services may file "on or before the date of receipt of payment", (c) the AD may extend the deadline. No services exemption or value threshold was found; the only carve-out in Reg. 3 is travellers' personal effects.
   - **The AD bank enters it into EDPMS.** Reg. 18(1)(b): the AD "shall enter details of EDF of service (of its customers) in EDPMS within five working days of receipt of EDF from an exporter."
   - **Exporters can switch AD banks.** Reg. 10(1): an exporter may route transactions "through any other Authorised Dealer provided the exporter has intimated the change to both the Authorised Dealers."
2. **The EDF form.** The Annex form (Part 1) has an "AD code" field, plus a separate "Name of the AD and AD code in case of LC/BG" field. This is from the triangulated reproduction in the 2026-10-07 note; the RBI Annex PDF (https://rbidocs.rbi.org.in/rdocs/content/pdfs/NRAR23R16012026_AN.pdf) is still CAPTCHA-blocked, including via the Wayback Machine.
3. **The Master Direction is superseded.** Directions: A.P. (DIR Series) Circular No. 20 (RBI/2025-26/194, 16 Jan 2026) says "With effect from the date these directions come into force [1 Oct 2026], the Master Direction – Export of Goods and Services and Master Direction – Import of Goods and Services … shall stand superseded" (https://www.rbi.org.in/Scripts/NotificationUser.aspx?Id=13278&Mode=0). Its text, as read via WebFetch, says nothing about the AD code. The old MD 16/2015-16 page (https://rbi.org.in/Scripts/BS_ViewMasDirections.aspx?id=10395, "updated" 17 Jul 2026) still carries the 2015-era lines "export such services without furnishing any declaration" and SOFTEX. **Do not cite them as current law.**
4. **SOFTEX is gone.** Software is a service, filed on the EDF (see the 2026-10-07 note).

### If the exporter leaves it blank

**Inference.** No bank states what happens. The bank receiving the EDF is the AD, already knows its own code, and keys the EDPMS entry itself (Reg. 18(1)(b)). The worst realistic case is that the bank asks for the code or writes it in. For goods, a missing or unregistered AD code blocks the shipping bill in ICES, but that path does not apply to services.

## Residual uncertainty

1. **The RBI Annex PDF** is unread (CAPTCHA). It might mark fields as mandatory, which would change the Q2 answer. Someone should open it in a browser once.
2. **"AD code = BSR Part-I of the AD branch"** is an inference from matching prefixes and the joint MOF allotment. No primary source states it outright.
3. **Whether a "14-digit" code is ever valid** (for example on bank letters) is unconfirmed. ICES only allows 10 characters.
4. **The DBIE Branch Locator's current fields** (whether it includes IFSC, and whether it can be downloaded without login) are unverified.
5. **Which AD code each bank wants on a services EDF** (account branch or central) is only shown for ICICI. Ask HDFC and Axis on the week-1 calls.

## Implications for Korra

1. **Make the AD code optional.** Today it is required in `packages/ui/src/forms/BankForms.tsx` (both forms), in `saveBankInput` in `packages/backend/src/inputs.ts`, and in the DB (`ad_code NOT NULL` in `packages/db/src/schema.ts`, migration `0000_init.sql`). No primary source makes the exporter supply it on a services EDF, and ICICI fills it itself. When it is blank, the PDFs should print an empty "AD Code:" box for the bank to fill, not the string "undefined". The places are `pdf.ts:61`, `pdf-hdfc.ts:193` and `declaration.ts:159`.
2. **Do not offer IFSC-based lookup or auto-fill.** There is no official mapping. A branch's own BSR code is wrong whenever the bank uses a central AD branch, as ICICI does, and a wrong code is worse than a blank one.
3. **Use soft validation only.**
   - Expect about 7 alphanumeric characters (alphanumeric since 2019).
   - Accept a pasted 14-digit or hyphenated value as-is rather than rejecting it.
   - A gentle hint is possible if the first 3 digits do not match the chosen bank's BSR prefix (HDFC 051, ICICI 639, Axis 636, SBI 000, Kotak 018). Even that would need a maintained table, so keep it out of v0.
4. **Help text**, for example: "AD code (optional). The code of the bank branch that handles your foreign exchange. It is usually 7 digits. Your bank knows it and can fill it in, so leave this blank if you don't have it. If your bank gave you an AD code letter, use the code on that letter. It is not your IFSC."
5. **Fix test fixtures.** They use plausible 7-digit values (`6390001`), and `browser.test.ts` uses `"123"`. None needs to change unless validation is added.
6. **Bank guides.** The ICICI guide can say ICICI pre-fills the AD code on its EDF. For HDFC and Axis, "ask your branch's trade desk" until confirmed.

## Per-bank central AD codes (2026-10-08 follow-up)

**Question:** can Korra pre-fill the AD code per bank, because the bank routes services EDFs and inward SWIFT remittances through one central AD branch with one code?

**Short answer:** only ICICI has a first-party, published central code (`6390002`), and even that comes with caveats. No other bank publishes one. HDFC's `0510005` turned out to be an ordinary New Delhi branch, not a central unit.

### Source used to identify branch codes

The Controller of Pension Accounts (Ministry of Finance) publishes per-bank BSR directories as XLSX at https://cpao.nic.in/Ministry/BSR.php. The download URLs are `https://cpao.nic.in/php4/ExcelForBanks.php?cd=<base64 bank code>`, for example `cd=MDUx` for HDFC. They return "Invalid Request: Missing Referer Header" unless the request is sent with `Referer: https://cpao.nic.in/Ministry/BSR.php`.

**Caveats:**
- It is a directory of **pension-paying branches** with their link and nodal branches. It is not an AD list, and it is incomplete: ICICI's `6390002` is not in it.
- Reading a branch's BSR Part-I code as its AD code still rests on the inference in "Format" above.
- Columns: `BANK_NAME, PAY_BSR_CODE, PAY_ADDRESS1/2, PAY_CITY, … LINK_BSR_CODE …, NODAL_BSR_CODE …, IFSC_CODE`.

### HDFC 0510005: which branch is it?

- **It is an ordinary New Delhi branch.** In the CPAO HDFC file, `0510005` is "HDFC BANK, 209-214, KAILASH BUILDING, 26, K G MARG, NEW DELHI 110001", IFSC `HDFC0000003` (https://cpao.nic.in/Ministry/BSR.php, file `cd=MDUx`). Aggregators agree: https://www.bankfrog.in/bsr-code/0510005 and https://www.bsrcode.in/hdfc-bank/0510005-hdfc-bank-new-delhi-bsr-code/.
- **The early codes are all old flagship branches.** Its neighbours in the same file are `0510001` Worli (Dr Annie Besant Road), `0510002` Tulsiani Chambers (Nariman Point), `0510003` Khar and `0510004` ITC Centre (Anna Salai, Chennai). Nothing marks `0510005` as a trade-ops or forex hub.
- **The screenshot is no evidence either.** It was a sample row on an ICEGATE test system (`localhost:8080`; see "Format" above), so it says nothing about HDFC's services-EDF routing.
- **HDFC's own letter points to the account branch.** It has a "Branch" field at the top, a blank "AD Code", and says "Documents may be submitted at the Trade Desk of your respective HDFC Bank Branch or through digital channel" (https://www.hdfc.bank.in/content/dam/hdfcbankpws/in/en/msme-banking/trade-service/fees-and-charges/pdfs/exports/edf-request-letter-tf-product.pdf; copy in `docs/research/assets/`).

### ICICI 6390002: how strong is it?

1. **ICICI's own EDF pre-fills it.** The form reads "Authorised Dealer (AD) Code: 6390002", with AD Name & Address "ICICI BANK LIMITED, Mumbai & CORPORATE OFFICE BRANCH, ICICI TOWERS BKC, BANDRA(E), MUMBAI … 400051" (https://www.icici.bank.in/content/dam/icicibank/icici-assets/nri-banking/export-declaration-form-development.pdf). This is first-party.
2. **ICICI links the form from its forms page and routes it centrally.** The page lists it under "Wire transfer / FCC transfer purpose of remittance declaration forms". The same section also has forms for resident individuals and proprietorships, such as Annexure 6, "Declaration from Resident Individual/Proprietorship for inward remittance…". Everything in that section goes to one central address: "ICICI Bank Ltd, RPC – NRI Cell, Autumn Estate, 5th Floor, "A" Wing, … Chandivali, Andheri (E), Mumbai – 400 072" (https://www.icici.bank.in/nri-banking/documents-form). So the inward-wire paperwork, including resident individuals', is processed centrally (first-party). The AD code printed on the form is the BKC corporate-office branch, which is not the Chandivali RPC.
3. **Only an aggregator confirms which branch the code belongs to.** https://www.bsrcodebank.com/bsr-code-6390002/bsr lists `6390002` as the BSR code of ICICI Towers BKC, 400051. It is absent from the CPAO file.
4. **Reasons for caution:**
   - The filename ends in `-development.pdf`.
   - The form also pre-fills an IE code, `IIHIE0153E`, which has the shape of a PAN-style IEC (5 letters, 4 digits, 1 letter). A web search finds nothing for it, and its 4th character "I" is not a standard PAN holder-type letter, so it looks like a placeholder or test value.
   - The PDF's author field is "/REMT/IBANK/THANE", which looks like an internal remittance-ops author, and it was created on 1 Oct 2026.
   - The code does **not** appear on ICICI's business-banking exporter page (https://www.icici.bank.in/business-banking/trade-solutions/solution-for-exporters) or its FIRC page (https://www.icici.bank.in/business-banking/trade-service/foreign-inward-remittance-certificate).
   - So the code is verified for ICICI's retail and NRI inward-wire channel. For current-account or trade-services customers, whom ICICI serves through its trade desks, it is unverified.

### Recommendation

1. **Pre-fill nothing by default except ICICI, and treat ICICI as a soft default.**
   - When the user picks ICICI, offer `6390002` as an **editable suggestion** with visible provenance, for example: "ICICI's own EDF form uses 6390002 (Mumbai corporate-office branch). Confirm with ICICI if you bank through a trade desk."
   - The value is first-party, and ICICI routes retail inward-wire forms centrally.
   - It is still a suggestion rather than a silent pre-fill: the source PDF looks like a draft (`-development`, placeholder IEC), and nothing confirms it for current-account or trade-services customers.
   - If this is too much for v0, use it as placeholder or hint text instead of a value.
2. **HDFC, Axis, SBI, Kotak, BoB, PNB, Yes, IDFC First, IndusInd: leave the field blank** and keep the "your bank fills it in" help text.
   - Never pre-fill HDFC `0510005`. It is a single New Delhi branch, and a wrong code is worse than a blank one.
   - Never derive a code from the IFSC or the BSR directory, for the reasons above.
3. **Revisit** if a bank publishes a services-EDF form with a pre-filled code, or if the week-1 bank calls confirm a central code. Ask HDFC, Axis and Kotak specifically: "Which AD code goes on a services EDF for a savings or current account at a non-trade branch?"
